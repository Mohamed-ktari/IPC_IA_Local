Root
architecture-ai/—Project root
├── .env—Secret keys, model names, ports — never committed to git
├── .env.example—Template of .env with placeholder values — committed so teammates know what's needed
├── .gitignore—Excludes .env, venv/, __pycache__, data/uploads, data/chroma
├── docker-compose.yml—Defines all services: backend, chromadb, redis, postgres, ollama — one command to start everything
└── README.md—How to install, run, and use the project
Backend — Core App
backend/app/—All Python application code lives here
├── main.py—FastAPI app entry point — registers all routers, starts the server, loads middleware
└── config.py—Reads .env and exposes a global settings object — every file imports from here, never reads .env directly
LLM Layer — provider abstraction
├── llm/
│ ├── base.py—Abstract BaseLLM class with chat() and stream() methods — defines the contract every provider must follow
│ ├── ollama.py—Ollama implementation of BaseLLM — calls local Ollama API on the server (Qwen 14B)
│ ├── factory.py—get_llm(agent_type) function — reads config and returns the right model instance with the right system prompt loaded
│ └── prompts/—Plain text system prompts — editable without touching code
│ ├── analysis.txt—System prompt for document analysis agent — instructs model to extract, structure, follow templates
│ ├── generation.txt—System prompt for document generation — instructs model to write formal French technical content
│ ├── proofreading.txt—System prompt for proofreading — instructs model to find errors, redundancies, inconsistencies
│ ├── regulatory.txt—System prompt for regulatory agent — instructs model to cite sources, apply CNIL/normes context
│ ├── coding.txt—System prompt for coding assistant — instructs model to generate clean Python/scripts with comments
│ └── vision.txt—System prompt for vision agent — instructs model to describe technical photos, identify equipment
Agents — one per specialized use case
├── agents/
│ ├── base_agent.py—Parent class all agents inherit — handles shared logic: loading prompt, calling LLM, logging, error handling
│ ├── analysis_agent.py—Feature 1 — receives a document + template name, retrieves relevant chunks via RAG, returns structured synthesis
│ ├── generation_agent.py—Feature 2 — receives a template + context, queries doc base for similar past documents, generates new DOCX content
│ ├── proofreading_agent.py—Feature 3 — receives one or multiple documents, runs consistency checks, returns structured report of issues
│ ├── regulatory_agent.py—Feature 4 — receives a query, calls search gateway (never internal docs), returns sourced regulatory answer
│ ├── coding_agent.py—Feature 5 — pure LLM agent, no RAG needed, handles script generation, code explanation, automation help
│ ├── report_agent.py—Feature 6 — receives raw data files (Excel, notes), applies report template, generates full structured report
│ ├── diagram_agent.py—Feature 8 — receives natural language description, generates Mermaid or SVG diagram, exports to file
│ └── vision_agent.py—Feature 9 — receives image file, calls multimodal Qwen-VL model via Ollama, returns structured description
│ └── extraction_agent.py—
│ └── rc_agent.py—
│ └── qa_agent.py—
Documents — ingestion & retrieval pipeline
├── documents/
│ ├── ingestion.py—Orchestrates the full pipeline: receive file → call right parser → chunk → embed → store in ChromaDB
│ ├── chunker.py—Splits extracted text into chunks — configurable size/overlap, aware of document type (technical docs need larger chunks)
│ ├── retrieval.py—Queries ChromaDB with an embedding, returns top-k most relevant chunks, optional reranking
│ ├── embedder.py—
│ ├── section_matcher.py—
│ ├── test_section_matcher.py—
│ └── parsers/—Each parser handles one file type and returns clean plain text
│ ├── pdf_parser.py—Extracts text from PDF — uses pdfplumber for digital PDFs, falls back to pytesseract OCR for scanned ones
│ ├── docx_parser.py—Extracts text and structure from Word documents using python-docx, preserves headings hierarchy
│ ├── excel_parser.py—Reads Excel sheets with openpyxl, converts tables to structured text or JSON for LLM consumption
│ ├── image_parser.py—Pre-processes images with OpenCV (contrast, denoise), then runs pytesseract OCR to extract any text
│ └── bim_parser.py—Parses IFC files with ifcopenshell — extracts element names, properties, materials as queryable text
│ └── document_cleaner.py—
│ └── config_reader.py—
Templates — company document structures
├── templates/—JSON files defining the expected output structure for each document type — edited by the company, not by devs
│ ├── amiante.json—Sections and fields expected in an asbestos diagnostic summary
│ ├── offres_entreprises.json—Reading grid for analyzing company bids
│ ├── memoire_technique.json—Structure for technical bid document analysis based on consultation regulations
│ └── rapport_audit.json—Template for automated energy audit or thermal study reports
Search — external internet access (RGPD-isolated)
├── search/
│ ├── gateway.py—PII firewall — sanitizes all queries before sending outward, logs every external call, enforces GET-only rule
│ ├── brave_search.py—Calls Brave Search API — returns raw results, no tracking, EU-friendly
│ └── sources/
│ ├── legifrance.py—Queries Légifrance API for current legislation and regulatory texts
│ └── normes.py—Fetches updates from technical standards sources (AFNOR, thermal norms, building regulations)
Output — document export
├── output/
│ ├── docx_writer.py—Takes structured LLM output and writes a formatted Word document using python-docx with company styles
│ ├── pdf_writer.py—Converts generated content to PDF — uses reportlab or weasyprint
│ └── svg_writer.py—Takes Mermaid or raw SVG from diagram agent and exports clean SVG file for use in Illustrator
API — HTTP routes
├── api/
│ ├── middleware.py—Runs on every request — checks auth token, writes audit log entry, handles CORS
│ └── routes/
│ ├── chat.py—POST /chat — receives message + agent_type, routes to correct agent, streams response back
│ ├── documents.py—POST /documents/upload — receives file, triggers ingestion pipeline, returns doc ID
│ ├── agents.py—GET /agents — returns list of available agents with descriptions for the frontend selector UI
│ ├── search.py—POST /search — triggers regulatory_agent with external search, returns sourced results
│ ├── qa.py—
│ ├── rc.py—
│ └── health.py—GET /health — checks Ollama, ChromaDB, Redis are reachable — used by Docker healthcheck
Audit — RGPD compliance
├── audit/
│ ├── logger.py—Writes structured log entry for every action: who, which agent, which document, timestamp, no content stored
│ └── models.py—Pydantic schema for a log entry — defines exactly what fields are recorded
Data — persistent storage (gitignored)
└── data/
├── uploads/—Raw files uploaded by users — never committed, backed up separately on the server
├── chroma/—ChromaDB vector database persistence — the embedded knowledge base of all ingested documents
└── logs/—Audit log files — retained according to company RGPD data retention policy
